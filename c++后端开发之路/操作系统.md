# 操作系统（OS）的概念
==控制和管理整个计算机系统的硬件和软件资源，合理组织计算机工作和资源分配，提供给用户和其他软件方便的接口和环境，它是计算机系统中的最基本**系统软件**==

1. 操作系统是系统资源管理者
	 处理机（cpu）管理
	 存储器管理
	 文件管理
	 设备管理
2. 向上层提供方便易用的服务
	 把一些丑陋的硬件功能封装成简单易用的服务，用户无需关心底层实现
	 
	 GUI：图形化用户接口
	 
	 联机命令接口=交互式命令接口（命令行）：windows：win+R，输入cmd回车
	 
	 脱机命令接口=批处理命令接口：windows：c盘中的*.bat文件，类似shell，一次处理多个命令
	 
	 程序接口（给软件/程序员做的）：可以在程序中进行**系统调用**来使用程序接口。不能直接使用，需要通过程序代码间接使用（==系统调用类似于函数调用，是应用程序请求操作系统服务的唯一方式==）

3. 是最接近硬件的一层软件
	 实现对硬件机器的拓展，没有任何软件支持的计算机称为**裸机**。操作系统可以将裸机改造成功能更强大，更方便的机器
	 
	 通常把覆盖了软件的机器称为扩充机器，又称之为**虚拟机**

# 操作系统的四大特征

**==并发，共享，虚拟，同步==**
**并发和共享是两个最基本特征，二者互为条件**

## 并发
并发：指两个或多个事件在同一时间间隔内发生，这些事件宏观上是同时发生的，**但微观上是==交替==的**

并行：指两个或多个事件在同一时刻**同时发生**（微观上也是同时的）

注意：
1. 单核cpu同一时刻只能执行**一个程序**，各个程序只能**并发**地执行
2. 多核cpu同一时刻可以执行多个程序，各个程序**可以并行**地执行
## 共享
即资源共享，是指系统中的资源可供内存中多个==并发执行的进程**共同使用**==

**共享方式:**
==互斥共享方式==：虽然某些资源可以提供给多个进程使用，但一个时间段内**只允许一个进程**访问该资源

==同时共享方式==：允许一个时间段内由多个进程“同时”（宏观上）进行访问

## 并发和共享的关系

1. **==有了并发性才需要共享性确保程序并发运行**==
2. **==没有并发性，共享性也就没有了意义==**

## 虚拟

指把一个物理上的实体变为若干个逻辑上的对应物。物理实体是实际存在的，而逻辑上对应物是**用户感受**到了


**==虚拟存储器技术（空分复用技术）**：可以实现4gb的物理运行内存，实现大于4gb程序同时运行（用户感觉）==

**==虚拟处理器技术（时分复用技术：把cpu的时间拆成时间片，给多个程序交替使用）**：一个单核cpu，在用户感觉起来好像有多个cpu同时为自己服务==

## 异步

指并发运行的程序，进程的执行不是一贯到底的，而是走走停停，以**不可预知的速度**向前推进，这就是进程的异步性==（用进程同步机制解决）==



# 操作系统的发展与分类

1. 手工操作阶段：程序员打纸带机->给计算机->计算机打纸带输出（人慢机快，计算机cpu使用率低）
2. 批处理阶段--单道批处理系统：加入磁带，人先将纸带通过一个机器弄到磁带上，加快纸带的读取输出速度
3. 批处理阶段--多道批处理系统（==操作系统正式诞生==）：**依旧使用磁带，但每次往内存中读入多道程序，可以并发运行程序。**（但没有人机交互功能，程序开始后，用户只能等着输出，无法进行调试）
4. 分时操作系统：计算机以==时间片==为单位==轮转为各个用户/作业服务==，各个用户可通过终端与计算机进行交互（但没有优先处理紧急进程的功能，对各个用户分的时间是公平的）
5. 实时操作系统：能优先响应一些紧急任务，某些紧急任务不需时间片排队（在严格的时限内处理完事件，**==可靠性，及时性==**）
	  硬实时系统：必须在绝对严格的规定时间内完成处理
      软实时系统：能接受偶尔违反时间规定
  


# 操作系统的运行机制

## 预备知识：程序是如何运行的？

**==“指令” 就是处理器（cpu）  能识别，执行的最基本命令（机器码）**==

两种程序：
1. 应用程序（例如qq，微信）（==只能使用非特权指令）
2. 内核程序（组成操作系统内核，简称内核（kernel））（==操作系统最重要核心部分，最接近硬件的部分==）（**==允许使用特权指令）

**CPU如何区分是哪种程序发出的指令？：

cpu有两种状态，**“内核态”**=核心态=**管态**，**“用户态**”=**目态**

处于哪个状态说明正在运行哪种程序。

CPU中的**程序状态字寄存器（PSW）**记录状态



开机时cpu是内核态
内核态->用户态：执行一条**特权指令**--修改psw的标志位为用户态，意味着操作系统让出cpu使用权
用户态->内核态：由**中断**引发，硬件自动完成变态过程，操作系统夺回cpu使用权，**并转而运行一段内核程序来处理这个中断信号**


# 中断和异常

## 中断的作用

==“中断”是让操作系统内核夺回CPU使用权的**唯一途径**。==

==“中断”可以不让一个应用程序一直进行，也是实现**并发**的关键技术==

## 中断的类型


1. 内中断（异常）：与当前执行的**指令有关**，中断信号来源于CPU**内部**
	1. 陷阱，陷入（由陷入指令引发，程序故意引起的）
	2. 故障（由错误引起，可能可以由内核程序修复，修复好后CPU使用权会归还应用程序）
	3. 终止（由致命错误引起，内核程序无法修复该错误，CPU使用权不会还给应用程序）
2. 外中断（中断）：与当前执行的**指令无关**，中断信号来源于CPU**外部**（比如时钟中断，I/O中断）（==每一条指令执行完毕后CPU都会检查一下是否有需要处理的外部中断）


**陷入指令/trap指令/访管指令**：有时候应用程序想请求操作系统内核的服务（系统调用），会执行一条陷入指令，引发一个**内部中断**，把CPU使用权还给操作系统，并运行服务

## 中断机制的基本原理

**不同的中断信号，需要用不同的中断处理程序来处理**

CPU检测到中断信号后，会根据中断信号的类型查询**中断向量表**，找到中断处理程序在内存中的位置，并运行



# 系统调用

**程序接口由一组系统调用组成**

**==系统调用是操作系统给应用程序（程序员）使用的接口，可以理解为一种可供应用程序调用的特殊函数，应用程序可以通过系统调用来请求获得操作系统内核的服务==**


## 系统调用与库函数的区别

**库函数更为上层，方便程序员用高级编程语言请求操作系统的内核服务（注意：有些库函数不涉及系统调用：如取绝对值函数）

普通应用既可以直接进行系统调用，也可使用库函数来请求操作系统内核服务


## 功能分类

1. 设备管理
2. 文件管理
3. 进程控制
4. 进程通信
5. 内存管理

**凡是与==共享资源（如上）==有关的操作，都必须通过系统调用的方式向操作系统内核提出服务请求，让内核代为完成，保证系统的==稳定性和安全性==**


## 系统调用的过程

1. 传递参数，指明系统调用类型
2. 应用程序发出==陷入指令==（用户态下进行，引发**内中断**）
3. CPU检测到内中断，转入相应的中断处理程序，**即系统调用入口程序**
4. 检测参数，确定是哪个类型的系统调用，然后运行

注意：**发出系统调用请求是在用户态，对系统调用的相应处理是在内核态下进行

# 操作系统的体系结构（未完待续）


1. 微内核（Windows，NT）：只包含**时钟管理**，**中断处理**，**原语**，这最接近硬件管理的部分（**更底层**）
2. 大内核（Linux，UNIX）：包含微内核，并且包含**进程管理，存储器管理，设备管理**等内容（这些多的内容主要管理的是一些数据结构）

**大内核性能更好，因为变态转换次数更少**（微内核每次用进程管理，存储器管理，设备管理时，都要进行两次变态）**而大内核只有应用程序申请大内核的两次变态**

微内核内核功能少，结构清晰，方便维护





# 操作系统引导（boot）

开机的时候，怎么让操作系统运行起来

电脑安装操作系统后，磁盘最前面会有一段被用于记录**主引导记录（MBR）（包含磁盘引导程序和分区表）

c盘装有操作系统，称为（**活动分区**）


c盘内部分为：引导记录（PBR）（用于找到“启动管理器”），根目录，其他

1. CPU从一个特定主存地址开始，取指令，执行ROM（BIOS）中的引导程序（先进行硬件自检，再开机）
2. 将磁盘的第一块--主引导记录读入内存，执行磁盘引导程序，扫描分区表
3. 从活动分区（又称主分区，即安装了操作系统的分区）读入分区的引导记录，执行程序
4. 从根目录下找到完整的操作系统初始化程序（即启动管理器）并执行，完成开机一系列操作


# 虚拟机

使用虚拟化技术，将一台物理机器虚拟化为多台虚拟机器（VM），每个虚拟机器都可以独立运行一个操作系统

同义术语：虚拟机管理程序/虚拟机监控程序/Virtual Machine Monitor（VMM）/Hypervisor

1. **第一类VMM**：直接运行在硬件上，将硬件资源划分给不同虚拟机，CPU划分时间片，硬盘划分一定空间。

**这类虚拟机的内核空间是第一类虚拟机管理程序，而非上层操作系统（变为虚拟内核空间），所以上层操作系统不能直接使用特权指令，需要被虚拟机管理程序截获并进行等价转换操作**


2. **第二类VMM**（类似VMware)：运行在宿主操作系统上

# 进程管理


## 进程的概念

程序：是静态的，存放在磁盘里的可执行文件，就是一系列的指令集合

==**进程：是动态的，是程序的一次执行过程（同一个程序多次进行会对于多个进程）**==

### 进程实体的组成
**1.（PCB：process control block）进程控制块**
1. ==进程的编号==（PID）（唯一不重复）
2. 用户编号（UID）
3. 进程分配了什么资源
4. 进程运行情况
5. 处理机相关信息
6. ...
	**但凡操作系统管理进程要用到的信息，都会被存在PCB中

==PCB是进程存在的唯一标志，当进程被创建时，操作系统为其创建PCB，当进程结束时，会回收其PCB==


**2. 程序段
程序的代码（指令序列）

**3. 数据段
运行过程中产生的各种数据（如程序中定义的变量）


**==PCB是给操作系统用的==**
程序段、数据段是给进程自己用的


**==进程是动态的，但是进程实体（进程映像）是静态的，进程实体反应了进程在某一时刻的状态（快照）==**

**所以：进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。**

## 进程的特征
1. 动态性（最基本特征）
2. 并发性
3. 独立性（独立获得资源，独立接受调度的基本单位）
4. 异步性
5. 结构性（结构统一）


## 进程的状态与转换

1. **创建态**：进程正在被创建，这个阶段操作系统会给进程分配资源，初始化PCB
2. **就绪态**：进程已经具备运行条件，但由于没有空闲的CPU，所以暂时不能运行（**除去处理机资源，其他资源都就绪**）
3. **运行态**：一个进程此时在CPU上运行，CPU会执行该进程对应的指令序列（**所有资源包括处理机都就绪了**）（==若时间片用完，进程会从运行态变为就绪态）
4. **阻塞态**：进程运行过程中，可能会请求等待某个事件的发生（如等待某种资源的分配），操作系统不会让它继续占用算力，而是让它下CPU，并变为阻塞态（==进程主动选择的）
	**当进程等待的那个事件发生了，进程就会从阻塞态又变回就绪态**（是一个被动行为）
5. **终止态**：进程可以执行exit系统调用，请求操作系统终止该进程，操作系统回收资源，回收PCB

# 进程控制

通过进程状态之间的变换，来实现对系统中所有进程实施有效的管理

**要用原语（内核态中运行）来实现进程控制**：为什么？**进程转换一般有多步，每一步都不可被打断**，否则会出错

==一般用**关中断指令**，和**开中断指令**，这两个**特权指令**来实现原语的原子性

**关中断指令：一旦执行这个指令，CPU就不会在每次指令完成之后例行检查有无中断信号，而是直到执行开中断指令之后才会恢复检查**

**开中断指令：恢复CPU中断信号检查**
