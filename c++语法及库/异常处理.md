C++ 异常处理核心结构：

```
try
{
    // 可能产生异常的代码
}
catch(异常类型 变量)
{
    // 处理异常
}
```
try里面放可能产生异常的代码，catch（**捕获throw**）在catch里处理异常

如果需要主动产生异常：

```
throw 异常对象;
```
这个异常对象可以是各种内置数据类型，也可以是自己自定义的类临时对象，自定义类型等，==**throw**后面必须是一个表达式==

完整流程：

```
try
 |
 | 执行代码
 |
 | 遇到 throw
 ↓
寻找匹配的 catch
 ↓
执行 catch
 ↓
继续后面的代码
```
try 本身不处理异常。

它只是告诉编译器：

> 这部分代码**可能**发生异常，请准备寻找 catch




```cpp
catch(int e)
{
    cout << e;
}
```
**含义** ：捕获int类型异常，并保存到e


# 捕获引用
实际工程中：

```cpp
catch(const std::exception& e)
{
    cout << e.what();
}
```

**因为异常通常是类对象**，如果不用引用很可能发生对象切片（类比多态需要用父类指针或引用来实现动态多态）


# 异常类型匹配规则（从具体到一般）

==c++寻找第一个能和抛出类型匹配的catch，并执行==
	catch顺序设计：**捕获子类的catch必须写在捕获父类的catch之前**，否则，永远会执行父类catch而到不了子类catch(**从具体到一般**)

因为一般包含了具体

# catch(...) 万能捕获
语法：

```cpp
catch(...)
{

}
```
三个点表示：

> 捕获任何类型异常

==但是通常无法知道错误是什么，所以通常放最后来提示未知错误==

# 栈展开

当函数嵌套调用中，某深层函数抛出异常，但当层没有catch，则返回上一层找catch，以此类推，找到catch为止

在这过程中，会自动释放经过函数的局部变量（**栈区变量**）

==**注意！！！**==：堆内存不会自动释放，也就是说new出来的东西不会执行delete！！！ ==所以要用智能指针，析构自动释放==






# 重新抛出异常

语法：

```cpp
throw;
```

注意没有对象。

例如：

```cpp
catch(exception& e)
{
    cout<<"记录日志";

    throw;
}
```

作用：

> 把当前异常继续向上传递。

常用于：

```
底层：
记录错误

上层：
决定怎么处理
```

因为不同层职责不同，比如repository层知道异常后，负责记录日志，ui层知道异常后负责显示到屏幕告诉用户


# 一个异常处理类的设计

	继承路线：标准库（exception)->BaseException->.....
这样的继承路线保证了可以使用const std::exception & 统一接收异常
私有类型：message（因为本质异常类就是告诉你错误信息是什么）
```cpp
#pragma once

#include <exception>
#include <string>


class BaseException 
    : public std::exception
{

public:

    explicit BaseException(
        const std::string& message
    )
        : message(message)
    {

    }


    const char* what() const noexcept override
    {
        return message.c_str();
    }//接口约定必须要返回const char*因为exception里的虚函数是这样定义的


private:

    std::string message;

};
```
explicit作用：防止发生构造函数隐式转换导致私自构造对象产生bug，==所有单参数构造函数都建议加explicit==(**禁止构造函数参与类型转换**)
noexcept作用：保证不会抛异常，若真抛异常则程序直接终止，用来激进性能


# 设计具体异常
通过单参数构造函数实现
```cpp
#pragma once

#include "UserException.h"


class UserNotFoundException
    : public UserException
{

public:

    explicit UserNotFoundException(
        int id
    )
        :
        UserException(
            "User not found, id="
            + std::to_string(id)
        )
    {

    }

};
```


异常类可以类内声明类内定义，因为太简单，一类只有一个构造函数
